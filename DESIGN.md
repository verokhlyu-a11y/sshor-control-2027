# СШОР Контроль — дизайн сайта для GitHub Pages

> Дизайн-спецификация и техническое задание. Версия 1.0, 23 октября 2026 года.

## 1. Назначение

«СШОР Контроль» — современная внутренняя панель спортивной школы: задачи, документы, контроль сроков, мероприятия и отчётность. На первом этапе сайт работает как демонстрационный прототип на GitHub Pages без персональных данных и закрытых документов.

## 2. Фирменный стиль

| Роль | Цвет | HEX |
|---|---|---|
| Основной тёмно-синий | Навигация, заголовки, кнопки | `#162B48` |
| Акцентный красный | Статусы, важные действия, активные элементы | `#EB3333` |
| Белый | Карточки, контрастный текст | `#FFFFFF` |
| Светлый фон | Подложка рабочей области | `#F4F6F9` |
| Основной текст | Текст и подписи | `#202B3B` |
| Вторичный текст | Подсказки | `#66758A` |
| Линии | Границы карточек | `#E2E7EF` |

Принцип: 75% светлых поверхностей, 20% тёмно-синего, 5% красного. Никаких зелёно-бирюзовых градиентов, случайных цветов, декоративных мазков и перегруженных фонов.

## 3. Визуальная концепция

- Стиль: минималистичная административная dashboard-панель с характером спортивного бренда.
- Чёткая сетка, крупные цифры, большие отступы, строгая типографика, тонкие разделители.
- Левое меню на тёмно-синем фоне, справа светлая рабочая область.
- Красный используется только как акцент, не как сплошная заливка большинства блоков.
- Карточки белые, скругление 14–18 px, лёгкая тень или тонкая обводка.
- Логотип СШОР в верхней части меню; предусмотреть свободное место для загрузки оригинального логотипа.
- Фото спортсменов — только там, где они помогают содержанию; на главном экране важнее данные.

## 4. Типографика

- Заголовки: **Manrope** 700–800.
- Основной текст и интерфейс: **Inter** 400–600.
- Числовые показатели: **Manrope** 700–800, табличные цифры.
- H1: 32–40 px; H2: 22–26 px; текст: 15–16 px; подписи: 12–14 px.
- Не использовать слишком узкие, декоративные или плохо читаемые шрифты.

## 5. Структура сайта

### Левое меню

1. Главная
2. Задачи и сроки
3. Документы
4. Мероприятия
5. Отчёты
6. Подразделения
7. Настройки

### Главная страница

**Верхняя панель:** «СШОР Контроль», текущая дата, поиск, аватар/иконка пользователя (демо).

**Первый экран:** заголовок «Панель управления» и подпись «Все ключевые процессы спортивной школы — в одном месте».

**Четыре KPI-карточки:** активные задачи, документы на согласовании, ближайшие мероприятия, просроченные поручения. Значения в демоверсии обозначать как демонстрационные.

**Основная область (две колонки):**
- Слева — «Задачи на контроле»: задача, ответственный, срок, статус.
- Справа — «Ближайшие события»: дата, вид спорта, событие.

**Нижняя область:** «Документооборот» с визуальной шкалой этапов: подготовка → согласование → подпись → регистрация. Ниже — быстрые действия: «Добавить задачу», «Открыть реестр», «Сформировать отчёт».

### Остальные страницы

- **Задачи:** таблица, фильтры по сроку, ответственному, статусу и подразделению.
- **Документы:** реестр и этапы согласования, поиск, карточка документа; не публиковать реальные служебные документы.
- **Мероприятия:** календарь тренировок, соревнований и внутренних событий.
- **Отчёты:** показатели по видам спорта и подразделениям, графики, выгрузка демонстрационных данных.
- **Подразделения:** Монино, Мытищи, Опалиха и другие подразделения по мере подтверждения структуры.

## 7. Адаптивность

- Desktop ≥1200 px: постоянное левое меню, 4 KPI в ряд, двухколоночный контент.
- Tablet 768–1199 px: компактное меню, 2 KPI в ряд.
- Mobile <768 px: меню-кнопка, 1 KPI в ряд, таблицы с горизонтальной прокруткой или карточками.
- Никаких выезжающих за экран заголовков; длинные слова должны переноситься корректно.

## 8. Техническая реализация на GitHub Pages

Рекомендуемая структура:

```text
/
├── index.html
├── assets/
│   ├── css/
│   │   └── style.css
│   ├── js/
│   │   └── app.js
│   └── img/
│       └── logo.svg
├── README.md
└── .nojekyll
```

- Для первой версии — обычные HTML, CSS и JavaScript без сборщика и без зависимости от Jekyll.
- Если используется `index.html`, убрать или переименовать конфликтующий `index.md`.
- Подключать CSS относительным путём `./assets/css/style.css` и JS `./assets/js/app.js`.
- Проверить регистр букв в путях: GitHub Pages чувствителен к нему.
- Не хранить в репозитории персональные данные спортсменов, пароли, токены, внутренние документы и сведения ограниченного доступа.
- GitHub Pages — статический хостинг. Реальное разграничение доступа, редактирование общих данных, авторизация и защищённый документооборот требуют отдельного серверного решения.
